# ПОЯСНИТЕЛЬНАЯ ЗАПИСКА
## к программному продукту «Lynk» - приложение для учёта персональных подписок

### 1. Введение

**1.1. Наименование программы:** «Lynk - приложение для учёта и контроля персональных подписок».
**1.2. Назначение:** Программа предназначена для ведения списка активных подписок (стриминговые сервисы, банковские услуги, мобильная связь и т.д.) с целью контроля расходов и своевременного отслеживания дат их продления.
**1.3. Платформа:** Десктопные ОС (Windows, macOS, Linux).
**1.4. Технологический стек:** Python 3.10+, PyQt6 (GUI), SQLite (встроенная СУБД).



### 2. Архитектура и структура проекта

Проект разделен на логические модули для соблюдения принципа разделения ответственности (Separation of Concerns).

**Структура папок:**
- `Lynk_QT/` - корневая папка проекта
- `.venv/` - виртуальное окружение Python
- `styles/` - папка с файлами стилей (содержит `dark.qss` и `light.qss`)
- `ui/` - папка с XML-шаблонами интерфейса (содержит `dialog_window.py` и `main_window.py`)
- `main.py` - основной файл (логика приложения и работа с БД)
- `lynk.db` - файл базы данных (создается автоматически)
- `requirements.txt` - список зависимостей проекта


*Примечание: Интерфейс загружается из XML-строк, хранящихся в файлах папки ui/, через uic.loadUi(io.StringIO(template), self).*



### 3. Структура базы данных (SQLite)

База данных `lynk.db` состоит из трёх таблиц. Для обеспечения уникальности названий подписок в таблице `subscriptions` установлено ограничение `UNIQUE` на поле `title`.

**Таблица `categories` (Таблица категорий):**
- `id` (INTEGER, PRIMARY KEY) - уникальный идентификатор.
- `name` (TEXT, UNIQUE) - название категории (Банк, Кино, Музыка и т.д.).

**Таблица `subscriptions` (Подписки):**
- `id` (INTEGER, PRIMARY KEY) - уникальный идентификатор.
- `title` (TEXT, UNIQUE, NOT NULL) - название подписки (защита от дубликатов).
- `end_date` (TEXT) - дата окончания в формате ISO 8601 (YYYY-MM-DD).
- `cost` (REAL) - стоимость.
- `category_id` (INTEGER, FOREIGN KEY) - ссылка на `categories.id`.

**Таблица `notifications_log` (Лог уведомлений):**
- `subscription_id` (INTEGER) - ID подписки.
- `notify_date` (TEXT) - дата уведомления.
- *Составной первичный ключ (subscription_id, notify_date) защищает от повторной отправки уведомлений в один день.*


### 4. Функциональные возможности

Приложение реализует полный CRUD-цикл (Create, Read, Update, Delete).

**4.1. Просмотр (Read):**
- Главное окно отображает данные в `QTableWidget`.
- Данные сортируются по дате окончания (ближайшие - сверху).
- Реализована цветовая индикация: **красный** (просрочено), **оранжевый** (истекает в ближайшие 3 дня).

**4.2. Добавление (Create):**
- Открывается модальное окно `DialogWindow`.
- Поле «Дата» по умолчанию установлено на +30 дней. С помощью `QDateEdit.setMinimumDate()` запрещен выбор прошедших дат.
- Валидация стоимости через `QRegularExpressionValidator` (разрешены только цифры и одна точка/запятая).

**4.3. Редактирование (Update):**
- Вызывается **двойным кликом** по строке таблицы.
- Открывается то же окно `DialogWindow`, но в него передается кортеж `new_data`. Окно автоматически заполняет поля текущими значениями из БД, меняет заголовок на «Редактирование» и текст кнопки на «Сохранить».
- При сохранении выполняется SQL-запрос `UPDATE`.

**4.4. Удаление (Delete):**
- Вызывается кнопкой «Удалить».
- Появляется диалог подтверждения (`QMessageBox.question`).
- Удаление происходит строго по скрытому `ID` записи, сохраненному в `Qt.ItemDataRole.UserRole`.

**4.5. Уведомления:**
- При запуске программа проверяет подписки, истекающие через 3 дня (`NOTIFY_DAYS`).
- Выводится всплывающее окно `QMessageBox.information` со списком.
- С помощью таблицы `notifications_log`, уведомление по одной подписке показывается только один раз в день.

**4.6. Смена темы:**
- Реализована кнопка «Тема». Стили загружаются из `styles/*.qss` и применяются глобально через `QApplication.instance().setStyleSheet()`.



### 5. Технические особенности и решения

1. **Защита от дубликатов (UNIQUE):** База данных на уровне схемы запрещает создание подписок с одинаковыми названиями. Обработка исключения `sqlite3.IntegrityError` в коде перехватывает эту ошибку и выводит пользователю понятное сообщение «Подписка с таким именем уже существует».
2. **Передача состояния (паттерн "Два в одном"):** Диалоговое окно используется для двух задач. Наличие или отсутствие параметра `new_data` в конструкторе (`__init__`) является флагом: если данные переданы - это редактирование, если нет - создание.
3. **Хранение скрытых данных:** В ячейке `item_title` (столбец 0) сохраняется `ID` записи через `item_title.setData(Qt.ItemDataRole.UserRole, id_)`. Это позволяет безопасно удалять и редактировать записи, даже если названия изменились.
4. **Валидация и ограничения:** `QDateEdit` не дает выбрать прошлую дату. Регулярное выражение `r"^\d*[.,]?\d*$"` блокирует ввод букв в поле стоимости, а запятая автоматически меняется на точку перед конвертацией в `float`.
