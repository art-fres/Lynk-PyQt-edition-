# Техническое задание (ТЗ) на разработку приложения «Lynk»

## 1. Общие сведения
*   **Название проекта:** Приложение для учета и контроля персональных подписок.
*   **Платформа:** Desktop (Windows, macOS, Linux).
*   **Рекомендуемый стек технологий:** Python 3.x, PyQt6 (GUI), **SQLite** (СУБД, встроенная в Python).
*   **Тематика интерфейса:** Темная тема (Dark Mode).

## 2. Цель и назначение
Приложение предназначено для ведения списка активных подписок (стриминговые сервисы, банковские услуги, мобильная связь и т.д.) с целью контроля расходов и отслеживания дат их продления.

## 3. Функциональные требования

### 3.1. Главный экран (Список подписок)
*   **Отображение данных:** Экран содержит таблицу (`QTableWidget`) со столбцами:
    *   **Название** (строка).
    *   **Дата окончания** (дата в формате `ДД.ММ.ГГГГ`).
    *   **Стоимость** (вещественное число, например, `2999.99`).
    *   **Категория** (строка, подтягивается из связанной таблицы БД).
*   **Кнопка «ДОБАВИТЬ»** — открывает модальное окно добавления новой записи.

### 3.2. Модальное окно «Добавление подписки»
Окно вызывается по кнопке «ДОБАВИТЬ» и перекрывает основной экран.
1.  **Название:** Строка ввода (`QLineEdit`), плейсхолдер «Введите название». Обязательное поле.
2.  **Дата:** Дата-пикер (`QDateEdit`), формат `ДД.ММ.ГГГГ`.
3.  **Стоимость:** Числовое поле ввода (`QLineEdit` с валидатором).
4.  **Категория подписки:** Выпадающий список (`QComboBox`). **Важно:** Список значений должен динамически подгружаться из таблицы `categories` базы данных.
*   **Кнопки:** «ОТМЕНА» (закрыть без сохранения), «ДОБАВИТЬ» (валидация, запись в БД, обновление главного экрана).

### 3.3. Системные уведомления (Пуш-уведомления)
Приложение должно поддерживать работу в фоновом режиме (в системном трее) и отправлять локальные пуш-уведомления средствами ОС (через `QSystemTrayIcon`).
*   **Триггер срабатывания:** Приближение даты окончания подписки.
*   **Правило уведомления:** Уведомление отправляется, если до даты окончания подписки остается **3 дня** (значение должно быть настраиваемым в коде/настройках).
*   **Формат уведомления:**
    *   *Заголовок:* «Скоро списание!»
    *   *Текст:* «Подписка [Название] закончится [Дата]. Стоимость: [Стоимость] руб.»
*   **Частота:** Проверка базы данных происходит фоновым таймером (`QTimer`) один раз в сутки (или при каждом запуске приложения). Уведомление по одной и той же подписке не должно спамить (отправляется 1 раз в день).
*   **Сворачивание:** При закрытии главного окна приложение не завершает работу, а сворачивается в трей (иконка в области уведомлений), продолжая отслеживать даты.

## 4. Нефункциональные требования (Дизайн и UX)
*   **Цветовая палитра:** Фон главного окна `#1a1c23`, фон модального окна `#2b3545`, кнопки `#556b8c`, текст и обводки `#ffffff`.
*   **Таблица:** Без сеток, только нижние разделители строк. Заголовки прозрачные.
*   **Стили полей ввода:** Поля в модальном окне стилизованы под линии (нижнее подчеркивание), выпадающий список — в рамке.
*   **Иконка в трее:** Приложение должно иметь иконку в системном трее с контекстным меню («Открыть», «Выход»).

## 5. Архитектура базы данных (SQLite)
Для обеспечения масштабируемости и чистоты данных используется реляционная структура **из двух таблиц** (связь «один ко многим»).

### 5.1. Таблица `categories` (Справочник категорий)
Хранит уникальный список возможных категорий.
*   `id` (INTEGER, PRIMARY KEY, AUTOINCREMENT) — Уникальный идентификатор.
*   `name` (TEXT, UNIQUE, NOT NULL) — Название категории (например, "Банк", "Кино", "Музыка", "Другое").

*При инициализации базы данных таблица должна быть автоматически заполнена базовыми значениями.*

### 5.2. Таблица `subscriptions` (Основные записи)
Хранит данные о подписках пользователя.
*   `id` (INTEGER, PRIMARY KEY, AUTOINCREMENT) — Уникальный идентификатор подписки.
*   `title` (TEXT, NOT NULL) — Название подписки.
*   `end_date` (TEXT, NOT NULL) — Дата окончания (хранится в формате ISO 8601: `YYYY-MM-DD`).
*   `cost` (REAL) — Стоимость подписки.
*   `category_id` (INTEGER, NOT NULL) — **Внешний ключ (FOREIGN KEY)**, ссылается на `categories.id`.

## 6. Этапы разработки (Roadmap)
1.  **Этап 1: Дизайн UI.** Верстка интерфейса (PyQt6 + QSS), создание иконки приложения.
2.  **Этап 2: Инициализация БД.** Написание скрипта создания двух таблиц, настройка связей и первичное заполнение справочника категорий.
3.  **Этап 3: Логика работы.** Написание обработчиков (добавление, загрузка списка категорий в ComboBox, вывод объединенных данных в таблицу главного экрана).
4.  **Этап 4: Уведомления и Трей.** Реализация сворачивания в трей (`QSystemTrayIcon`), настройка фонового таймера (`QTimer`), парсинг дат из БД и вывод всплывающих окон ОС.
5.  **Этап 5: Тестирование и сборка.** Проверка работы уведомлений (эмуляция дат), сборка в исполняемый файл `.exe`.
